## 1. 诉求（现象）

1. 复现步骤：
   1. 打开任一张图的图片详细画面（`image-detail/{id}`）
   2. 底部编辑区内容较多（已选标签多、重命名区 + 库标签/自定义标签等叠高）
2. 实际结果：主图被纵向挤得很小，几乎不可浏览；下方虽挂了 `verticalScroll`，但编辑区按内容固有高度参与 Column 测量，滚动未真正生效
3. 期望结果：主图保留**最低高度**（或固定高度/占比；用户口述「最低宽度」，竖排布局按**高度**理解，接票时锁定具体值）；下方编辑区在剩余空间内滚动，超高不继续挤占主图

## 2. 必读路径

- `project-docs/画面/图片详细画面/README.md` §5（主体：主图 → 重命名/标签 → 缩略条）
- `project-docs/画面/图片详细画面/主图缩放.md` §4（「占主体主要高度」）
- `android/.../ui/imagedetail/ImageDetailScreen.kt`（`ZoomableImage` `weight(1f)` + 编辑区 `Column(verticalScroll)` **无** `weight` / `heightIn`）
- 近源：[F9](../功能体验/F9-标签收起与弹选.md)（库标签 >10 收起，减轻但未根治已选很多时的挤占）；[F4](../功能体验/F4-详情放大收起编辑区.md) / [T1](../调查/T1-详情放大挡手势.md)（放大藏编辑区，与 scale=1 常显挤占无关）

## 3. 验收

- [ ] 编辑区内容很多时，主图仍不低于约定最低高度（或固定高度），可正常浏览/缩放
- [ ] 超出剩余高度的编辑内容可纵向滚动，不把主图继续压扁
- [ ] 缩略条仍可见；scale>1 时 F4/Bug5 行为不回退
- [ ] 编辑区较少时主图仍可占满剩余空间（不低于下限即可）
- [ ] 文档 §4/§5 与实现一致（补最低高度约定）
