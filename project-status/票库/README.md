# 票库 · 起票制（project-status/票库/）

> 任何改动先起票、再接票。**待办仪表盘**：当前开放阶段 [待对应](../阶段/阶段4-维护与迭代/待对应.md)（现为阶段 ④；排除搁置）；下一号：[阶段/README](../阶段/README.md)。  
> 规则亦见根 `README.md` · [`dev-convention`](../../shared/rules/dev-convention.md)。

> **路径约定**：票内链到规格用 `project-docs/`；同分区票用 `./票号-….md`；跨分区用 `../bug|功能体验|调查|式样变更/…`。旧 `docs/` / `式样/` / `改动清单` / 开发日志已迁走或删除——已闭票正文于 2026-09-18 批量改链；若仍见断链请报。

## 1. 票类型（四种）

| 前缀 | 类型 | 用途 | 分区 | 完结后 |
|---|---|---|---|---|
| `BugN` | Bug | 已确认错误 | [bug/](bug/) | 保留 |
| `SN` | 式样变更 | 已确认式样 / 需求变化 | [式样变更/](式样变更/) | 保留 |
| `TN` | 调查 | 先查再定方案 | [调查/](调查/) | 保留 |
| `FN` | 功能 / 体验 | Android 产品功能或体验（含工具链 / 公开包装） | [功能体验/](功能体验/) | 保留 |

AI 仓库（prompts / workbench 等）改动：用 **FN**（节点常 `P`），票内注明范围；**不**再单独设「结构」类型。

## 2. 状态写在哪（防三处漂移）

| 写什么 | 哪里 |
|---|---|
| ☐ / 🚧 | **票正文** + **必须**进当前开放阶段 `待对应.md` 一行（有票号写票号；状态列写 ☐/🚧） |
| ✅ / ❌ | **票正文**；从 `待对应.md` **删行**；✅ 写入该阶段 `票目录.md` |
| 搁置 | **票正文**；进阶段 `票目录.md`「搁置」表（**不**进待对应） |
| 下一号 | **仅** [阶段/README](../阶段/README.md) |
| 分区 README | **只**票号 · 标题 · 文件链接（不抄状态） |

**硬性**：无 ☐/🚧 票可只存在于票正文却不在 `待对应`——禁止。新会话「做到哪了」只看待对应，不靠全库 grep。

## 2.1 新票挂哪一阶段（写死）

阶段 ③ 已闭合后：一切未闭票（Bug / S / T / F，含 AI 体系 FN·P、产品 V）一律进 **[阶段4 · 待对应](../阶段/阶段4-维护与迭代/待对应.md)**；**不**再往阶段2 / 阶段3 `待对应` 加行。  
阶段2 / 阶段3 `票目录` 仅作已完成历史索引；新 ✅ 写入阶段4 `票目录`。

## 3. 无票改动（二选一，写死）

凡改仓库但**不起产品/调查票**的清理、更名、纯文档整理：

1. **进下方「附记」**一行（日期 + 做了什么）；或  
2. **起极简 FN（节点 P）**，票内写清范围后按正常闭环。

禁止第三种：对话里改完、附记与票都无痕迹。

## 6. 状态机

```
☐ 待实施 → 🚧 进行中 → ✅ 已完成
                ↘ ❌ 不采纳
另：搁置
```

调查「值得做」→ 转新票（原票 ✅ 并注明转号）；「不值得做」→ ❌。验收后补完结复盘；教训可进 [错题本](../../ai-workbench/错题本.md)。

## 7. 生命周期

| 阶段 | 动作 |
|---|---|
| 起票 | 复制模板 → `.md` → 分区 README 加一行 → **当前开放阶段** `待对应.md` 加 ☐ 行；推进下一号 |
| 接票 | 票 → 🚧，同步待对应状态列；`prompts/票_接票开发.md` |
| 实施 | 文档先行 → 代码 → 票内记录（黄红） |
| 验收 | 用户 ✅ / ❌ → 复盘 → 待对应**删行**；✅ 写入阶段 `票目录`；分区表不加状态列 |
