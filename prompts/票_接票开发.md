# 接票开发（按票执行）

**用法**：把本文件拉进对话 → 在下方「本次接票」填票号与票目录 → 发送。  
**约定**：起票制 · 文档先行 · 式样「待定」不擅自实现 · **一票一会话**。适用于 Bug / 式样变更 / 调查 / 功能体验 全类型票。

▶ include `ai-workbench/宪法/include约定.md`

---

## AI 执行流程（不用改）

收到「本次接票」后，按序执行：

1. **读票定边界**
   - 读 `project-status/票库/<分区>/<票号>-简述.md`（类型 / 状态 / 诉求 / 验收 / **关联画面·预估**）
   - 未起票 → 停，请用户按 `ai-workbench/模板/票/` 起票
   - ▶ include `ai-workbench/细则/接票/拆票门槛与档位.md`（命中 ≥2 条则停、建议拆子票；本会话不写码）

2. **读文档定边界**
   - ▶ include `ai-workbench/细则/接票/读文档定边界.md`

3. **对照票内容**
   - 缺画面文档 / 式样条目 → 先补文档再写码
   - 「待定」或规格不清 → 回票澄清，不猜

4. **定点读码**：只读将改文件及同包相邻（`android/app/src/`），禁止无目的扫全库

5. **先测后写判断**
   - ▶ include `ai-workbench/细则/接票/先测后写.md`

6. **方案与实现**
   - ▶ include `ai-workbench/细则/接票/拆票门槛与档位.md`（填票内「已锁定 / 实施步骤 / 档位」；绿档可极简）
   - 默认先列拟改文件与验收点，等确认再写；填写区写了 `直接实现` 则跳过确认
   - 合入：读 git 约定「合入方式」——`direct-main` 不主动开 PR；`via-mr` 默认开 PR

7. **收尾**
   - ▶ include `ai-workbench/细则/接票/收尾与验收自评.md`

**硬性约束**

- ▶ include `ai-workbench/细则/接票/硬性约束.md`
