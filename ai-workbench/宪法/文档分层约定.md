## 0. AI 开发闭环

`prompts/` + `shared/` **连接** `ai-workbench/`，以项目真相为输入、以 `android/` 为改动目标，改完再回写真相：

```
prompts/         拉入对话的编排壳
shared/          rules · skills 编排壳（同步到工具）
    ↕ ▶ include
ai-workbench/    指南 / 宪法 / 细则 / 模板 / 错题本
    ↓ 读取
project-status/  票库 · 状态 · 阶段
project-docs/    android 现状规格
    ↓ 变更
android/         唯一代码工程
    ↓ 写回
project-status/ · project-docs/
```

| 环节 | 目录 | 职责 |
|---|---|---|
| 怎么干 | `prompts/` · `shared/` | 编排壳；rules / skills（同步 `.cursor` / `.codebuddy`） |
| 干活材料 + AI 元文档 | `ai-workbench/` | 指南 · 宪法 · 细则 · 模板 · 错题本（**不是**产品规格正文） |
| 读什么 | `project-status/` · `project-docs/` | 票与是否实现、画面/架构等现状；当前开放阶段 ④ |
| 改什么 | `android/` | Kotlin / Compose / Gradle |
| 写回什么 | `project-status/` · `project-docs/` | 状态与规格对齐；**过程写在票内**（开发记录 / 完结复盘），不另建 logs |

禁止颠倒：不把产品规格写进 `prompts/` / `shared/` / `ai-workbench/`；不把 AI 纪律写成 `project-docs` 正文。

## 3. 先选世界再落目录

新文档先判世界，再进对应目录。禁止「先写再找地方」。

| 问自己 | → |
|---|---|
| 这是票 / 阶段待对应 / 排期 / **是否实现**？ | `project-status/`（状态看票内 + `阶段/*/待对应.md`；票正文在 `票库/`；当前开放为阶段 ④） |
| 这是错题本 / 阶段复盘 / 画面·票模板 / **分层宪法·落位**？ | `ai-workbench/` |
| 这是架构 / 路由 / **画面规格** / 已实现业务与数据层说明？ | `project-docs/`（= android 现状镜像；画面用 `project-docs/画面/`） |
| 这是过程 / 开发流水？ | **票内**开发记录与完结复盘（+ git）；**不**单独建 logs 目录 |
| 这是拉入对话的**提示词流程**？ | `prompts/` |
| 这是 AI **纪律 / 技能**？ | `shared/` |
| 两者都沾？ | 拆成两份：真相在 `project-docs/` / `project-status/` 等，流程在 `prompts/`，纪律/技能在 `shared/`，材料与元文档在 `ai-workbench/`，互相链接 |

AI 元文档变更须回写 [AI配置落位.md](AI配置落位.md) 盘点表。

## 4. 拆 / 不拆门槛

命中 **≥2 条**才把一篇长文拆成「短索引 + 分册」：

1. 单文件明显变长，且含 ≥3 个可独立读的主题
2. 接票经常只需要其中一章
3. 已有自然章节边界

**不拆**：

- 单主题或短文（如 [路由设计.md](../../project-docs/路由设计.md)）
- 时间线：开发日志、单张票、开发记录附录
- 已是一目录一主题（画面、票）
- 高频 AI 锚点必须留在权威路径（架构 **§2** 在 `project-docs/架构设计.md`）

不删内容，只搬家。权威入口文件名不改。搬家时旧路径**默认可**留短跳转——权威已迁且用户明确要求删除跳转时，可不留（如曾在 `shared/` 的宪法跳转）。**整目录已清空且无读者依赖时（如曾删仓库根 `docs/`）可不留跳转。**

## 5. 索引页与分册写法

### 5.1 索引（长文变短文）

1. 文首「AI 阅读入口」3～7 条（路径 + 节号）
2. 每章：2～5 行摘要 + **位置**（相对链接到分册）
3. 高频锚点（如架构 §2、式样 §5 画面表）可全文留在索引

### 5.2 分册

- 保留原节号（`### 4.1 导入` 仍叫 4.1），旧票写「式样 §4.1」仍能对上
- 文件名：`project-docs/` 用直白名（如 `核心流程.md`）
- 分册开头一行：所属索引路径（整理期可省略）

## 6. 各类生成模板

| 类型 | 怎么生成 |
|---|---|
| 式样 / 设计说明 | 索引 + 按门槛分册；落 `project-docs/` |

| 票 | 复制 [模板/票/](../模板/票/) → `project-status/票库/<分区>/<票号>-简述.md` |
| 过程记录 | 写在票「开发记录 / 完结复盘」；**勿**新建 `logs/` 或按日散文件 |
| AI 元文档（宪法/指南类） | 落 `ai-workbench/宪法/` 或 `指南/`，并回写落位盘点表 |
| 提示词 / rules / skills **编排壳** | 落 `prompts/` 或 `shared/`；细则用 ▶ include（见 [include约定.md](include约定.md)） |
| 细则正文 | 落 `ai-workbench/细则/` |

## 7. 读法（给人 / 给 AI）

1. 先票或当前 prompt 填写区 → 再按 §0 闭环选读
2. 打开该世界入口 README，**不通读**整库
3. 打开权威索引，按「位置」只开需要的分册
4. 禁止把式样 / 架构 / 本宪法全文粘进 alwaysApply rules
