# 3.3 PDD Prompt 驱动开发

Prompt-Driven Development：最轻量模式。不写 Spec、不写测试，直接对话迭代。

## 流程

```
人提需求（一句话）
    ↓
AI 生成初版
    ↓
人看效果 → 描述问题
    ↓
AI 修改 → 满意则结束
```

迭代粒度可极小：「密码太短加红色提示」「按钮上移 4px」。

## 价值与风险

| 价值 | 风险 | 缓解 |
|------|------|------|
| 零门槛、极快 | 多轮后上下文混乱 | 关键节点重置会话 |
| 适合探索 | 无 Spec 难回溯 | 里程碑 Git commit |
| 无文档负担 | 质量靠人眼 | 关键逻辑手动测 |
| | 方向漂移 | 固定一段核心需求在上下文前 |

## 适用 / 不适用

| 适合 | 不适合 |
|------|--------|
| MVP、个人小工具 | 大型多模块项目 |
| UI 微调 | 多人协作（缺文档） |
| 需求尚不明确 | 高正确性模块（无测试） |
