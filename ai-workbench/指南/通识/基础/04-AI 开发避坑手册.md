# 1.5 AI 开发避坑手册

16 条常见问题，按输入 → 规划 → 生成 → 质量 → 工具 → 适配分类。严重度：高 / 中 / 低 / 致命。更新于 2026-10。

## 1. 输入质量

**核心：喂对信息，比喂多更重要。**

### 问题 1：AI 不遵循项目规范与已有依赖（高）

- **现象**：能跑但重复造轮子，不用已有组件库
- **根因**：AI 不知道项目里有什么
- **对策**：Skill 要求「先查组件库再实现」；Rules 约束风格与目录

### 问题 2：三方库 API 过时（高）

- **现象**：调用已删除的参数或 API，编译/运行报错
- **根因**：训练数据滞后于库版本
- **对策**：挂载官方文档 Skill 或 MCP，给最新参考而非凭记忆

### 问题 3：Skill 全量加载（中）

- **现象**：上下文被占满，反而找不准该用哪个
- **对策**：Plan 阶段做意图识别，**只加载相关 Skill**

## 2. 任务规划

**核心：拆得对比跑得快更重要。**

### 问题 4：需求不明确时卡住（中）

- **对策**：先写 Spec（哪怕会改）。有方向比空等好；变更时再更新 Spec

### 问题 5：整页丢给 AI（高）

- **现象**：效果差、耗时长、易偏航
- **对策**：按 Layout 区块拆 Task；无依赖区块并行；最后合并

### 问题 6：拆分后重复代码（中）

- **对策**（优先级从高到低）：
  1. **设计阶段**：Plan 里定义公共方法目录
  2. **合并阶段**：合并时让 AI 提取重复
  3. **TDD 前置**：测试里先抽公共接口

### 问题 7：未定义公共层（高）

- **现象**：多个 formatDate、fetchWrapper 并存
- **根因**：公共方法需人提前定义，不能指望 Agent 自行识别
- **对策**：Plan 划公共层；Team Agent 各 Session 注入公共模块 Skill

## 3. 代码生成

**核心：按影响范围选策略，不一刀切。**

### 问题 8：小改动走完整 SDD（高）

| 改动范围 | 策略 |
|----------|------|
| 只改计算逻辑 | 只改 plan + task |
| 极小 UI | 直接改或插件辅助 |
| 需求本身变了 | 重走 spec → plan → task |

也可：改 UT → 反向驱动代码 → 同步 plan/task。

### 问题 9：TDD 在需求模糊时边界不全（中）

- **对策**：精度敏感用字符串等方式规避浮点；维护边界 Checklist 写测试时逐项核对

## 4. 质量控制

**核心：AI 写代码，人必须把关。**

### 问题 10：不做 Review（致命）

- **对策**：必须 Diff Review；可用 AI Review Skill 辅助检查目录、库、规范

### 问题 11：修 Bug 后文档不同步（高）

| Bug 级别 | 处理 |
|----------|------|
| 小（实现细节） | 只改代码 |
| 业务级（理解偏差） | 同步改 spec → plan → task → 重 implement |

原则：**代码改了，文档必须同步。**

## 5. 工具配置

### 问题 12：改工具内置 Template，升级丢失（低）

- **对策**：用 Hook 注入逻辑，或项目级 Template 覆盖，**不改工具源码**

## 6. 项目适配

### 问题 13：存量项目水土不服（高）

- **现象**：生成代码与现有架构、风格不一致
- **对策**：定制 Skill + Template，说明技术栈、组件库、编码习惯；可用率可从 ~80% 提到 ~90%

### 问题 14：上下文塞满当「长窗口福利」（高）

- **现象**：1M 窗口整库粘贴，中间规范失效、账单按长上下文倍率跳
- **根因**：Context Rot；注意力预算有限
- **对策**：JIT 检索 + 渐进 Skill；常驻只留 `AGENTS.md` / 短 Rules。见 [1.7](06-上下文工程.md)

### 问题 15：默认上多 Agent（中）

- **现象**：token 翻数倍、互相覆盖、摘要失真
- **对策**：仅在上下文可隔离或需要独立验证时拆；验证用黑盒子代理。见 [4.2](../协作/02-Team%20Agent%20多智能体.md)

### 问题 16：长跑 Agent 只听「做完了」（致命）

- **现象**：Projects / 云 Agent 跑一夜，PR 空壳或测了假路径
- **对策**：工单写 VERIFY/DONE；反向四问（真相、制品、接线、测试证明了什么）。见 [3.7 GSD](../开发模式/07-GSD%20编排驱动开发.md)
