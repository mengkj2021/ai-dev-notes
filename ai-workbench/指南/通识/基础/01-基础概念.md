# 1.1 基础概念

AI 辅助开发的核心概念，按层次分组。概念关系速查见文末。

## 交互层：如何与 AI 沟通

### Prompt（提示词）

发给 AI 的指令文本，决定 AI 看到什么、如何回答。长任务里 Prompt 只是上下文的一部分，整体编排见 [1.7 上下文工程](06-上下文工程.md)。

| 类型 | 说明 | 示例 |
|------|------|------|
| System Prompt | 设定角色与边界，通常用户不可见 | 「你是一名资深前端工程师…」 |
| User Prompt | 每次对话的具体输入 | 「帮我写一个表单组件」 |
| Few-shot | 给示例让 AI 照样式输出 | 2–3 个代码示例 + 同类生成要求 |
| Chain-of-Thought | 要求分步推理 | 「先分析需求 → 列步骤 → 写代码」 |

### Context（上下文）

AI 执行任务时可获取的全部背景：当前文件、对话历史、Rules/Spec、MCP/RAG 检索结果等。

- 有 token 上限，信息多不等于效果好
- 过长时易出现 **Lost in the Middle** / **Context Rot**：中间或过长内容召回变差
- 工程目标：每次推理只放**高信号、最小充分**的 token

## 约束层：如何控制 AI 行为

### Rules（规则）

项目级或用户级约束，声明 AI **必须/禁止** 做什么。

- **项目规则**：`.cursor/rules/*.mdc`、`.codebuddy/rules/` 等，随仓库共享
- **用户规则**：跨项目生效（如 Cursor Customize → Rules）
- 典型内容：代码风格、命名规范、禁用库、架构约定

### Skill（技能） / Agent Skills

打包好的**任务级行为规范**，偏向「遇到某类任务怎么做」，而非全局禁止。跨产品格式以 [agentskills.io](https://agentskills.io) 为准：目录 + `SKILL.md`。

- 含方法论、API 说明、示例、可选脚本
- 路径示例：`.cursor/skills/<name>/SKILL.md`
- **渐进披露**：先只加载 name/description；相关时再读正文；引用文件与脚本按需读取（脚本进上下文的是输出不是源码）
- 与 Rules 区别：Rules 管边界，Skill 管流程
- 2026-09：MCP Skills 扩展（SEP-2640）已 Final，Skill 可通过 `skill://` 资源分发，宿主与 SDK 仍在落地

### Hook（钩子）

在 Agent 生命周期特定节点自动执行脚本：生成前 lint、编辑后格式化、提交前测试等。

- 配置：`hooks.json` + `hooks/` 脚本目录
- 典型节点：beforeShellExecution、afterFileEdit、beforeSubmitPrompt

## 扩展层：如何增强 AI 能力

### MCP（Model Context Protocol）

开放协议，让 AI 通过 MCP Server 调用外部工具与数据（文件、数据库、浏览器、API）。可理解为「AI 的工具 USB 接口」。

- 核心协议修订：`2026-07-28`
- 可选扩展：Tasks（长任务异步）、Skills over MCP、MCP Apps（对话内 UI）
- 工具宜少而清：功能重叠的工具集会让 Agent 选错

### RAG（检索增强生成）

用户提问 → 向量检索相关文档 → 拼入 Prompt → 生成回答。适用于代码库问答、规范检索、企业文档。

- **MCP** = 工具调用协议
- **RAG** = 信息检索策略
- 两者可组合：MCP 提供检索工具，RAG 定义怎么用检索结果

## 流程层：如何组织开发

### Spec（规格）

结构化需求文档，描述**做什么**（非怎么做），供 AI 解析并拆任务。

- 含：功能概述、页面/路由、数据模型、接口、验收标准
- 与普通需求文档区别：粒度更细、可逐条校验

### Template（模板）

Spec / Plan / Task 等产物的标准格式，保证 AI 输出结构一致。

### SDD（Spec-Driven Development）

以 Spec 驱动全流程：写 Spec → 生成 Plan → 拆 Task → 逐条实现 → 验收。详见 [3.1 SDD 规约驱动开发](../开发模式/01-SDD%20规约驱动开发.md)。

### 人在环（Human-in-the-Loop）

人是设计者、决策者、验收者；AI 是执行者。重大决策与人审查不可省略。

## 智能体层

### Agent（智能体）

能自主规划、调用工具、多步执行任务的 AI 单元：思考 → 行动 → 观察 → 调整。常用定义：**在循环里自主用工具的 LLM**。

- **单 Agent**：一个模型独立完成
- **Subagent（子代理）**：主控派生子任务，**独立上下文**，只回蒸馏摘要；适合检索、验证、隔离污染
- **Multi-Agent / Team Agent / Coordinator**：多角色分工，主控调度（如 Cursor Projects 的 coordinator 自己不写代码）

Subagent 不是默认更快：有 I/O 契约时优于把长 Skill 塞进主上下文；协调开销常见为数倍 token。见 [4.2 Team Agent](../协作/02-Team%20Agent%20多智能体.md)。

## 概念关系速查

| 概念 | 一句话 | 层 |
|------|--------|-----|
| Prompt | 发给 AI 的指令 | 交互 |
| Context | AI 可见的全部背景 | 交互 |
| 上下文工程 | 每次推理放哪些 token | 交互 |
| Rules | 必须/禁止做什么 | 约束 |
| Skill | 某类任务怎么做（渐进加载） | 约束 |
| Hook | 流程节点自动逻辑 | 约束 |
| MCP | 连接外部工具的标准协议 | 扩展 |
| RAG | 检索增强回答准确性 | 扩展 |
| Spec | 结构化需求规格 | 流程 |
| Template | 标准化输出格式 | 流程 |
| SDD | 以 Spec 驱动全流程 | 流程 |
| 人在环 | 人决策验收，AI 执行 | 流程 |
| Agent | 自主规划执行多步任务 | 智能体 |
| Subagent | 独立上下文的子任务执行 | 智能体 |
