# 1.2 进阶概念

与 [01-基础概念](01-基础概念.md)、[06-上下文工程](06-上下文工程.md) 配套，偏模型机制。

## Context Window（上下文窗口）

模型一次可处理的最大输入长度，以 token 计。2026 年编码旗舰常见 **200K–1M**；Claude Code 对 Opus 4.7+ / Fable 默认 1M（可用环境变量退回 200K）。

- 窗口越大，跨文件分析能力越强
- 窗口大 ≠ 效果好；仍有 Context Rot
- 部分厂商对超长输入按 **2× 费率**计（如部分 GPT 超过约 272K）

## Token（词元）

模型处理文本的最小单位，由分词器切分，**不是**字或词。

- API 按输入/输出 token 计费；另有 **cache read/write**（命中缓存远低于原价）
- 粗估：英文 ≈ 0.75 word/token；中文 ≈ 1–1.5 字/token；代码接近英文
- 新 tokenizer（如部分 Claude Sonnet 5 系）同一段输入可能映射出更多 token

## Embedding（嵌入向量）

文本 → 高维向量，用于语义相似度与检索。

- 流程：文档 Embedding → 存入向量库 → 提问 Embedding → 相似检索 → 返回片段
- 常用：OpenAI text-embedding、Cohere Embed、BGE / 各厂商托管向量
- RAG 的预检索步骤依赖 Embedding；Agent 编码更常 **JIT 搜文件**，不替代向量库于文档问答

## Tool Use / Function Calling

模型输出结构化调用参数，由宿主执行后把结果回传。Agent 能操作文件、查库、发请求的基础。

- **Tool Use**：能力本身
- **MCP**：工具如何描述与调用的标准化协议（可叠加 Skills / Tasks 扩展）

常见工具类型：文件读写、Shell、HTTP、数据库、浏览器、MCP Server。

## Compaction 与 Cache

| 机制 | 作用 |
|------|------|
| Prompt cache | 重复前缀（Rules、长 Spec）只付一次写入，后续廉价读取 |
| Compaction | 对话过长时压缩历史，保留目标与决策 |
| 输出上限 | 少数前沿模型输出也可到极长（如 Gemini 4 Argon 宣称 1M 输出，2026-09 仅受限计划） |
