# 1.6 AI 开发方法论

## 一、脚本化原则

**洞察**：把一次高成本 AI 对话沉淀为脚本，重复执行时 token 趋近于零。

| 维度 | 全程 AI 对话 | 脚本化 |
|------|--------------|--------|
| 首次成本 | 几千 token | 写脚本一次性几千 token |
| 重复成本 | 每次几千 token | 0 token |
| 速度 | 等模型响应 | 本地毫秒级 |
| 批量 | 难 | 易循环 |

- **适合脚本化**：规则明确、重复执行（扫描重复资源、批量格式化）
- **保持对话**：需要理解、判断、每次输入不同（分析崩溃、探索方案）

## 二、CLI 与 IDE 分工

### CLI 的本质

通过终端与工具交互。CodeBuddy、Claude Code、Codex、Cursor Agent CLI 等都是「固化的一次（或一串）AI 对话」。例如 `aapt-res res-dup` ≈ 「扫描重复资源」。

2026 年 CLI Agent 已是一线形态：难任务用 Claude Code / Codex；IDE 负责预览与人审。Cursor 3 把云 Agent 和 IDE 做成可交接，而不是二选一。

### 分工

| | CLI | IDE |
|---|-----|-----|
| 使用者 | AI、脚本、CI | 人 |
| 交互 | 一条命令一个结果 | 持续对话、边看边改 |
| 上下文 | 弱，需手动描述 | 强，自动读项目 |
| 优势 | 批处理、可组合 | 直观、低门槛 |

好工具 = **底层暴露 CLI 给自动化 + 上层 GUI/IDE 给人**，互补而非替代。

### CLI 为何更快

省掉：项目索引（IDE 常 5–30 秒）、UI 渲染、等人看完再回复。

### CLI 适用场景

| 场景 | 工具 |
|------|------|
| 日常写代码、调 UI | IDE |
| 首次搭建、探索 | IDE |
| 难推理、大重构、无 GUI | CLI Agent（Claude Code / Codex） |
| 批量多项目处理 | CLI |
| CI/CD 检查 | CLI / Hook |
| 跨会话大功能 | Projects 或 GSD 文件，而不是无限 Chat |

### 边界说明

- CLI Agent（Claude Code / Codex）已是难任务主力，日常调 UI 仍以 IDE 为主
- 跨会话大功能用 Projects 或 GSD，不靠把聊天无限续下去
