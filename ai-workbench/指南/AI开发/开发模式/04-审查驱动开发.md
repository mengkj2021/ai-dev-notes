# 3.4 审查驱动开发

Review-Driven Development：AI 当「初级开发者」先出活，人做 Code Review，AI 按意见改。

## 流程

```
人给需求（Spec 或一段话）
    ↓
AI 自主生成代码
    ↓
人 Diff Review（逻辑、命名、安全、错误处理）
    ↓
AI 批量修改 → 再审 → 通过则合并
```

## vs SDD

| 维度 | SDD | Review-Driven |
|------|-----|---------------|
| 规范时机 | 先 Spec 后编码 | 先编码后审查 |
| AI 自由度 | 低 | 高 |
| 质量保障 | Spec + Task | Review |
| 适合 | 精确控制 | 先看 AI 能做什么 |

## 适用 / 不适用

| 适合 | 不适合 |
|------|--------|
| 存量项目小改动 | AI 完全跑偏且无 Spec 兜底 |
| 需求模糊，先看效果 | 大量文件变更（人审不过来） |
| 熟悉代码的人审 AI | 有硬性准入标准且无 Review 资源 |

必须 Diff Review，见 [4.6 人在环](../协作/06-人在环（Human-in-the-Loop）.md)。
