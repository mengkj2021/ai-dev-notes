# 3.6 混合模式

真实项目很少全程只用一种模式。按任务类型与阶段**动态切换**。

## 模式选择

| 情况 | 推荐模式 | 原因 |
|------|----------|------|
| 需求明确、功能大 | SDD | Spec 防跑偏 |
| 接口/逻辑可测 | TDD+AI | 测试定义行为 |
| 原型/探索 | PDD | 零门槛 |
| 不确定 AI 能力 | Review-Driven | 先看再定 |
| 批量/多模块并行 | Agent-Driven / Projects | 人介入最少 |
| 日常开发 | Mixed | 按任务切换 |

## 典型生命周期

1. **探索**（PDD）：「登录页大概长什么样」→ 快速原型
2. **正式开发**（SDD）：定原型 → Spec → Tasks → 执行
3. **关键模块**（TDD+AI）：支付/权限 → 人写测试
4. **UI 微调**（PDD）：间距、颜色秒改
5. **审查**（Review-Driven）：Diff Review → 修正
6. **CI/CD**（Agent-Driven）：全量测试、部署脚本

## 切换原则

- 需求越明确 → SDD、TDD（约束在前）
- 需求越模糊 → PDD、Review-Driven（先试再定）
- 任务越机械 → Agent-Driven
- 风险越高 → 人控制越强

## 目录级示例

```
src/
├── pages/      ← PDD（UI 迭代）
├── services/   ← TDD+AI（有测试）
├── features/   ← SDD（新功能有 Spec）
└── utils/      ← Agent（批量脚本）
scripts/        ← Agent（CI 自动化）
```

所有正式项目实质都是混合模式；问题不是「用不用」，而是「怎么混更合理」。
