# 手动三目录维护约定 · 细则

> 供 `shared/rules/sync-convention.md` ▶ include。

本项目由 CodeBuddy、Cursor 与 DeepSeek Harness（DSH）共同维护。项目说明见 `shared/README.md`；仓库根 `AGENTS.md` 有工具总表。

## 规则文件位置

| 工具 | 文件位置 |
|------|----------|
| CodeBuddy | `.codebuddy/rules/<name>/RULE.mdc` |
| Cursor | `.cursor/rules/<name>.mdc` |
| DeepSeek Harness（DSH） | `.dsh/rules/<name>/RULE.mdc` |

技能（skills）三处同理：`.codebuddy/skills/<name>/SKILL.md`、`.cursor/skills/<name>/SKILL.md`、`.dsh/skills/<name>/SKILL.md`。

## 各工具怎么加载

| 工具 | 规则 | 技能 |
|------|------|------|
| CodeBuddy | 会话开始注入常驻 rules，改后需**新建对话** | 目录内 `SKILL.md` |
| Cursor | `.cursor/rules/*.mdc`（`alwaysApply`） | `.cursor/skills/`（项目技能自动发现） |
| DSH | 工作区指令**只自动注入**根 `AGENTS.md` / `CLAUDE.md`（项目内逐级就近）；`.dsh/rules/` **不注入**，须按 `AGENTS.md` 指针或按需打开 | `.dsh/skills/<name>/SKILL.md`（项目技能自动发现，改后即时生效） |

DSH 不接受 Cursor 的 `globs` / `alwaysApply` 等字段，但会忽略不认识的键；规则壳保持同一份文本即可。

## 强制约定

1. **新增**：先在 `shared/rules/<name>.md` 创建，再复制到三个工具目录
2. **修改**：先改 `shared/rules/<name>.md`，必须同时更新三处，禁止只改一处
3. **删除**：`shared/rules/` 与三个工具目录一并删除
4. **frontmatter**：统一含全部字段，各工具忽略不认识的字段
5. **生效时机**：CodeBuddy 需新建对话；Cursor 规则改动后重开会话或重新加载；DSH 的 `.dsh/skills/` 改后即时刷新，`AGENTS.md` 改动在下一次请求生效

## 细则正文

细则正文变更时：先改本分册 → 确认编排壳仍 ▶ include 本文件 → 再同步三个工具目录中的编排壳。

## 自动校验（F56）

`scripts/check-shell-sync.mjs` 比对上面 6 组壳 × 4 份共 24 份文件是否逐字一致（行尾归一化后比内容）：

| 用法 | 口径 |
|------|------|
| `node scripts/check-shell-sync.mjs` | 工作区文件（人工核对、pre-push 主门禁） |
| `node scripts/check-shell-sync.mjs --root <目录>` | 把该目录当仓库根（pre-push 用它比对远端基线 `REF` 的已提交内容） |

`.githooks/pre-push` 每次 push 都先跑工作区那一遍，**漂移即中止 push**（紧急跳过：`git push --no-verify`，不推荐）；随后跑已提交内容那一遍，只警告不拦。脚本还兼检「同名技能散落在 `.agents/skills/` 等非镜像目录」——那会让 DSH 静默用到旧副本。

## 勿提交边界

`.gitignore` 放行 `.codebuddy/rules` / `.codebuddy/skills`、`.cursor/`（未忽略，整目录入库）、`.dsh/rules` 与 `.dsh/skills`；工具私有产物（`.codebuddy/plans/`、DSH 会话与凭据目录等）不入库。
