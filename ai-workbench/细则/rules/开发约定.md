# AI 全量开发约定 · 细则

> 供 `shared/rules/dev-convention.md` ▶ include。

本项目**全部代码由 AI 开发**（Kotlin 业务、Compose UI、Gradle 配置、文档）。Android 工程在仓库 `android/`。

## 用户职责

- **起票**：任何改动先起票（四类，见 `project-status/票库/README.md`），确认待定项
- Review diff、决定是否 commit / push

## 默认开发流程

1. **票**：先有票；接票读类型 / 状态 / 诉求 / 验收；「待定」先澄清
2. **文档**：新画面按路由 §4 复制 `ai-workbench/模板/画面文档/` → `project-docs/画面/<名>/`，更新路由表与画面清单
3. **代码**：按画面文档实现（`android/app/src/`），注册 route
4. **日志**：票开发记录（带票号）；☐/🚧 回写票正文 **且** 进当前开放阶段 `待对应.md`；✅ 删待对应行并写 `票目录`；分区 README 不加状态
5. **Review**：用户验收 → ✅ / ❌ → 再提交
6. **无票改动**：票库 README 附记，或起极简 FN（P）；禁止无痕迹（票库 README §3）
7. **挂阶段**：阶段3 已闭合 → 新票一律进阶段4 `待对应`（票库 §2.1）

## 权威文档（按需）

全量入口见仓库根 `README.md`。高频：`ai-workbench/宪法/文档分层约定.md` · `project-docs/` · `project-status/阶段/`（待对应 / 下一号） · `prompts/` · `ai-workbench/宪法/AI配置落位.md`

## 强制约定

1. **票驱动**：无票不进代码（例外见上文「无票改动」二选一）；待定先确认
2. **未确认项**：式样「待定」不得擅自实现
3. **新画面**：先画面文档目录，再代码
4. **route**：全小写、多词连字符（路由设计 §2）
5. **依赖**：同步 `libs.versions.toml` 与技术栈版本矩阵
6. **票号贯穿**：日志与 commit 带票号
7. **包结构**：`project-docs/架构设计.md` §2；改布局先改该节
8. **一票一会话**：独立新会话；收尾完成前不接下一票；续接同号须先回写 🚧
9. **读文档剂量**：先票与关联路径；禁止通读全库；不得把规格粘进 alwaysApply rules（落位见 `AI配置落位.md`）
10. **拆票**：▶ include `ai-workbench/细则/接票/拆票门槛与档位.md`
11. **票内步骤**：接票先确认步骤/档位；绿档可极简；分支见 git 约定
12. **文档分层**：以 `ai-workbench/宪法/文档分层约定.md` 为准；元文档在 workbench，执行件在 `prompts/` / `shared/`

## 维护入口

`shared/README.md`；宪法 / 落位 / include 约定在 `ai-workbench/`。
