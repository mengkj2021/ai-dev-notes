# 收尾与验收自评

> 供 `prompts/票_接票开发.md` ▶ include。

## 验收对照自评（必须先于回写 ✅）

读票「验收标准」每一条 → 按下表写证据（改了哪、验证了什么）→ **全部 ☑ 才可**回写 ✅ / 提交验收。任一条 ☐：先补做，再重做本步，禁止带缺口回写 ✅。含纯逻辑且已测的项，证据优先引用测试结果（命令与通过情况）。

自评写入票「开发记录 / 完结复盘」（可同时贴在回复里），格式：

```
### 验收对照自评（票号）

| 验收项 | 结果 | 证据（改了哪 / 验证了什么） |
|---|---|---|
| （从票「验收标准」逐条抄录，勿改写） | ☑ | `path`：改了…；验证：… |
| （下一条） | ☐ | （未达标则停，补做后再自评） |
```

全部 ☑ 之后才进入下面的回写。

## 回写清单

1. 回写票：状态（🚧 → ✅ / ❌）、开发记录 / 完结复盘
2. **回写「关联画面 · 实际改动」**（无画面可写「无」）：列出本票改过的 `project-docs/画面/…` 路径；仅代码且文档已对齐则写「无需改文档」
3. 补「完结复盘」；有复用价值的教训登记 [`错题本.md`](../../错题本.md)
4. 回写 **阶段4** [`待对应.md`](../../../project-status/阶段/阶段4-维护与迭代/待对应.md)（**删行**）；✅ 写入阶段4 [`票目录.md`](../../../project-status/阶段/阶段4-维护与迭代/票目录.md)（历史阶段票目录仅当确属该阶段遗留）；推进 [阶段/README](../../../project-status/阶段/README.md) 下一号（若本票用掉了号）；分区 README 若缺本票则**只加一行链接**，不写状态列
5. 依赖变更同步 `project-docs/技术栈.md` 版本矩阵（若涉及）
6. **一票一会话**：本票收尾并提交后结束本会话；下一张票请用户**新开对话**再拉提示词接票
