# 拆票门槛与档位

> 供 `prompts/票_接票开发.md` ▶ include。常驻 rules 只留短句。不引入 `.planning/`，不强制每票四窗口 / Autonomous。  
> 主题名「拆票门槛与档位」；**勿**与产品票号（如 F29 教程长文）混读。

## 拆票门槛（命中 ≥2 条 → 建议拆成新号子票）

1. **多交付物**：≥2 个可独立验收的用户可见结果
2. **跨层可切开**：数据迁移 / 新画面 / 纯流程约定等，切开后各自仍有意义
3. **待定可剥离**：大块待定可先开调查票，或先做已锁定子集
4. **会话装不下**：预估实施步骤 ≥5，且中段可单独验收
5. **需并行**：多方向要同时改不同模块

未达门槛 → **一张票 + 票内步骤**。子票用**新号**（分区下一可用号），关联栏写母题；不用 `F28.1` 后缀。写法见该车道 [`票库/README.md`](../../../examples/project-status/android/票库/README.md)「母题与子票」（其它车道同结构）。

## 档位与分支

| 档 | 大致范围 | 分支 |
|---|---|---|
| 绿 | 单点小改、无迁移/无新画面、步骤 ≤2 | 不强制；可在当前分支改 |
| 黄 | 多文件或有迁移/新交互、步骤 3–4 | **建议**开 `ticket/票号-简述`，不强制 |
| 红 | 新画面+数据层、步骤 ≥5、或多子票并行 | **应当**开 `ticket/…`（合入方式 `direct-main` 时可选，见 F31） |

例外：本票已在当前分支提交过半，不必中途再开 `ticket/` 分叉。merge / push 由用户决定，禁止擅自 `--force`（见 `git-convention`）。合入是否走 PR 见同文件「合入方式」开关。
