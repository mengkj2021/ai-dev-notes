# 起票分析 · 细则

> 供 `prompts/票_起票分析.md` ▶ include。只落盘票，**不改代码**。票库规则见 `project-status/票库/README.md`。

1. **读输入与票库现状**
   - 续号**只认** [阶段/README](../../../project-status/阶段/README.md)「下一号」（不得臆断；分区 README 无状态列）
   - 输入逐条归类：Bug / 式样变更 / 调查 / 功能体验
2. **文档优先分析**
   - 按根 README 与 [`文档分层约定.md`](../../宪法/文档分层约定.md) 定位项目相关文档与既有票（重复则只指不建）
   - 判断类型、现状、影响、「待定」；填「关联画面 · 预估」（「实际改动」留空）
3. **文档不足 → 定点读码**：只读定位到的 `android/app/src/` 文件
4. **归类产出**
   - 能归类 → 拟票；待定 / 不清 → 优先调查票或列问题；无法归类 → 回问
   - ▶ include `ai-workbench/细则/接票/拆票门槛与档位.md`（命中 ≥2 条则拆新号子票）
5. **落盘**：复制 `ai-workbench/模板/票/`（绿档四块）→ 分区目录；填节点（[票代号与节点](../../模板/票/票代号与节点.md)）；分区 README **只加一行链接**；**阶段4** [待对应](../../../project-status/阶段/阶段4-维护与迭代/待对应.md) 加 ☐ 行（阶段3 已闭合）；推进下一号；关联互记
6. **回执**：已建票清单（含节点）+ 预估画面；注明近重复

**硬性约束**：一票一主题；票号只进不退；☐/🚧 必须出现在待对应；只建票不改码与文档正文；commit / 开发纪律见 `shared/rules/`。
