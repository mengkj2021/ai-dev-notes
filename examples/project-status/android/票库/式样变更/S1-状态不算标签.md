## 变更内容（已确认的式样）

- 现状：原实现把状态词（待处理 / 已确认 / 不修改）作为「状态标签」注入 `ImageListItem.tags` 并写入 Room `tagsJson`（详情保存、移动、导入时都会拼进标签首位），与式样书旧条款「确认完成也是一个标签」冲突
- 变更为：**状态仅由 `status` 字段 + 主画面三 Tab 分类表达，不作为标签出现在标签库 / `tagsJson` / 筛选 / 打包用户标签中**；`tagsJson` 仅存用户标签
- 保留行为：详情仍把状态名作为保留字禁止输入为用户标签；三 Tab、移动、删除、打包、Exif 双写、重命名 `{tag}`、筛选「未打标签」行为不变（读端早已按用户标签处理）
- 历史数据：存量 Room `tagsJson` 由启动迁移幂等剔除残留状态词；存量 Exif 不回写（读端 `readUserTags` 已过滤）

## 验收标准（详见开发日志）

1. 新导入 → DB `tagsJson` 无状态词；主画面 chip 只显示用户标签
2. 移动后 `status` 更新、`tagsJson` 不含任何状态词，用户标签原样保留
3. 详情增删改标签 / 库多选 / 套模板 → `tagsJson` 无状态词；输入状态名仍被拒并提示
4. 打包分组、筛选、重命名 `{tag}`、Exif 回读均不出现状态词
5. 升级自旧版本：列表 chip 不再显示状态词，任一次写操作后 DB 即干净
