## 现象（用户可观察）

1. 复现步骤：详情画面打开图片 → 双指放大（已明显大于 1x）→ 观察文件名（顶栏）/ 标签区。
2. 实际结果：**有时放大到超过 1x 了，文件名、标签仍不消失**；整体"动作也有点怪"（放大 / 单击唤出 / 双击复位的触发时机不稳定，隐藏与显示跟手不够自然）。
3. 期望结果：按 F4 语义——scale>1 即默认隐藏文件名/标签，缩回 1x 恢复；单击唤出、双击复位各就各位，无"该藏没藏"。

## 影响范围

- 涉及画面 / route：图片详细画面 `image-detail/{imageId}`（主图缩放 + 顶栏 + 重命名/标签区）
- 涉及数据或文件：无（纯 UI 状态问题，怀疑缩放状态与隐藏状态不同步）

## 根因（调查后填）

- 初步判断（待验证）：F4 的"隐藏"依赖 scale 判定或"强制显示"标记——可能路径：① 放大瞬间 scale 判定时机（瞬时值 / 未做阈值或 debounce）错过切换；② 此前单击过主图置了"强制显示"标志，后续放大不解除，导致"放大了也不藏"；③ tap（单击唤出）与缩放手势（detectTransformGestures / 双击）竞争，动作判定互相干扰。
- 定位证据：`ZoomableImage` 叠两个 `pointerInput`（transform + tap）；捏合结束抬指常被识别为 `onTap` → `forceShowEditor=true`；且 `forceShowEditor` 仅在回到 1x 时清零，继续捏合不会再藏。

## 方案（接票后填）

- 文档改动：`docs/画面/图片详细画面/主图缩放.md` 补 Bug5 行为（捏合/平移取消强制显示；变换后短时忽略伪单击）
- 代码改动点：`ImageDetailScreen.kt` — `ZoomableImage` 短时窗抑制伪 tap；`onTransform` / `onScaledChanged` 清 `forceShowEditor`；回调 `rememberUpdatedState`
- 验证方式：捏合 >1x 编辑区立刻藏且松手不闪回；单击可唤出；再捏合再藏；双击回 1x；缩略条切换后状态一致

## 完结复盘（✅ / ❌ 后填；票与台账行保留，不删除）

- **此 bug 的产生原因**（根因链，非表面现象）：F4 实现把 `detectTransformGestures` 与 `detectTapGestures` 分两个 `pointerInput` 叠放，捏合结束的抬指序列易被当成单击并置 `forceShowEditor`；同时强制显示只在回到 1x 时清除，放大路径无法再藏。
- **为什么此前没被发现 / 防不住**（F4 验收未覆盖的路径）：F4 验收以「放大→隐藏→单击显示→双击 1x」为主路径，未覆盖「捏合松手后编辑区是否误闪回」与「强制显示后继续捏合是否再藏」。
- **修改是否带来新风险**（若有，转新票或备注）：350ms 抑制窗可能让「捏合后立刻单击唤出」略迟钝；若真机觉得过长/过短可另票调参。TopAppBar 文件名标题仍常显（不在 F4 范围）。
