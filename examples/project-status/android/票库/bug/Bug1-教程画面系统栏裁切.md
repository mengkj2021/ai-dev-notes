## 现象（用户可观察）

高版本 Android（edge-to-edge）上教程画面上下被系统栏 / 安全区裁切：顶部「跳过」顶进状态栏区，底部「下一步 / 开始使用」被导航条遮挡。

## 影响范围

- 涉及画面 / route：`TutorialScreen`（教程画面，首启与设置→查看教程两条入口）
- 涉及数据或文件：仅 UI 壳层

## 根因（调查后填）

- `MainActivity` 调用 `enableEdgeToEdge()`，内容默认延伸到系统栏之下
- 项目内普通画面均套 M3 `Scaffold`（自动消费系统栏 inset）；唯独 `TutorialScreen` 为裸 `Column` + 固定 16dp padding，未处理 inset

## 方案（接票后填）

- 代码改动点：`TutorialScreen.kt` 外层 `Column` → M3 `Scaffold`（无 topBar / bottomBar），content 应用 `innerPadding` 后再叠原 16dp padding
- 验证方式：API 30+（手势导航 / 挖孔屏）首启与「查看教程」路径走查

## 验收标准

- [x] API 30+ 首启进入教程：顶部「跳过」不被状态栏遮挡；底部页指示 + 按钮完整显示在导航条之上
- [x] 设置 →「查看教程」路径同样正常，返回行为不变
- [x] 3 页滑动 / 跳过 / 开始使用行为不变

## 完结复盘（✅ / ❌ 后填；票与台账行保留，不删除）

- **此 bug 的产生原因**（根因链，非表面现象）：画面壳层使用不一致——多数画面走 M3 `Scaffold`（隐式消费 inset），教程画面是唯一裸 `Column` + 写死 padding 的画面，edge-to-edge 下没有兜底
- **为什么此前没被发现 / 防不住**：inset 处理靠「套 Scaffold」这一惯例而非强制约定；低版本无 edge-to-edge 或不作检查即看不出裁切
- **修改是否带来新风险**（若有，转新票或备注）：无（1 文件改动，结构与交互不变，仅随 inset 内缩）
- **错题本登记**：不适用（已归档；无另立错题条目）
