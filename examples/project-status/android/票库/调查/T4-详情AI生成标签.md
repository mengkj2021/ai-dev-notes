## 要调查的问题

- 问题描述：在图片详细画面加一个「连接 AI」入口，把当前图片交给 AI，自动产出候选标签——技术路线是否现实、与项目定位是否兼容、成本几何。
- 为什么需要查清（若不查清的后果）：本项目当前定位「**全程本地运行、不联网**」（[AndroidManifest.xml](../../../../android/app/src/main/AndroidManifest.xml) 注释明示不声明网络权限；根 README 简介亦强调本地）；加 AI 若隐含联网 / 上云 / 引入 key，会直接触碰产品定位与隐私承诺，属方向性决策，必须先调查再定，不能凭印象直接起功能票。

## 已知线索

- 涉及画面 / 代码 / 文档 / 数据：
  - 画面：[图片详细画面 · 标签](../../../../project-docs/画面/图片详细画面/标签.md)、标签管理（候选标签 / 自动入库 S2）
  - 现状约束（写实）：
    1. **无网络权限、无网络库**：Manifest 未声明 `INTERNET`；技术栈（[式样书 §技术栈](../../../../project-docs/项目概述.md)）无网络 / HTTP 依赖；
    2. 图片存 **App 私有目录** `filesDir/images/{pending,confirmed,no_modify}`，用户以「本地整理私人照片」为使用场景；
    3. 标签体系已成型：图片 `tagsJson` + 全局词表 `tags`（S2 自动入库）——AI 产出的标签若要落地，应复走现有入口（选词 / 入库语义已定，不能绕开）；
    4. App 无任何账号 / 后端，唯一网络设施是「打包导出到本机 / FileProvider 分享」类本地能力。
- 已排除的可能：非「AI 生图 / 滤镜」类，用户指的就是**看图出标签**。
- 猜测与分歧点：
  - 云端多模态 API：效果最好，但需 `INTERNET` + 网络库 + **API key 管理与费用** + **图片上传第三方**——与「本地私人相册」定位冲突面大；
  - on-device 方案（本地视觉模型 / ML Kit 图像标注）：无网络但模型体积、标签语言（中文）、精度、维护成本待查；
  - 「折中形态」：功能做成**显式可选、默认关**的实验项，或仅对用户勾选/分享出去的图片生效——但仍绕不开上述基础问题；
  - 另需拍板：谁出 key / 费用、失败降级行为、是否只读不写（AI 只建议、用户确认才打标签）等。

## 调查方法与输出（接票后填）

- 方法：读式样书 / 架构 / 标签文档 + 依赖清单（`libs.versions.toml`）+ AndroidManifest，对照「AI 看图出标签」的可行路线。
- 调查结论（2026-09-03，证据见票内「已知线索」）：
  1. **技术上完全可行**：让模型看图产出中文标签在 2026 年是成熟能力（云端多模态 API 效果最好；本地模型质量差一档且中文标签依赖额外处理）。
  2. **真正的决策点不在「能不能」，而在「接不接受云端」**：本项目现状是"全程本地、不联网、不声明网络权限、用户私人照片存私有目录"（Manifest 注释 + 式样书定位均为写实）。云端路线 = 声明 `INTERNET` + 引入网络库 + **图片上传第三方** + **API key 管理**——逐条都在改产品定位与隐私承诺；本地路线（ML Kit / TFLite）则精度与中文标签不达预期、且 ML Kit 依赖 GMS（国内设备不可用）。
  3. **工程量本身不大**（若接受云端）：网络层 + key 存储 + 详情页一个"AI 建议"入口 + 建议结果 Chip（复用现有标签语义，用户确认才落库）≈ 1 张功能票的量级；R8 与 minSdk 26 无阻碍。难度集中在：key 不入仓库的安全存放、费用失控防护、失败降级、以及"建议 vs 自动打"的语义边界。
- 可选方案（3 选 1，待用户拍板）：
  - **A. 不做（维持纯本地定位）**：T4 ❌ 关闭。理由：AI 生成标签与"本地私人相册"定位相悖；公开叙事（AI 开发一个完整 App）不依赖此功能。
  - **B. 做"AI 建议标签"实验功能（云端、默认关）**：设置里填 key（本机保存，风险提示）；详情页点「AI 建议」→ 模型看图产出候选标签 → 用户勾选确认才写入 tagsJson（不自动打、不破坏现有打标签语义）。推荐若投：这是唯一与隐私承诺可共存于「显式开启」之下的形态，且可作公开后的功能亮点。若现在做 → 转 F13；若公开后做 → 暂搁置。
  - **C. 搁置（保持调查结论，不投入）**：T4 保持 🚧/☐ 存档，公开前主线（测试找 bug）不受扰，公开后再议。

## 后续动作

- **2026-09-03 用户拍板：选 C（搁置），近期不实现**。
- 近期不实现的原因（记录在案）：
  1. **与产品定位不符**：App 明确定位「全程本地运行、不联网、不声明网络权限」（AndroidManifest 注释即承诺），云端 AI 需 `INTERNET` + 图片上传第三方，直接改写隐私承诺；
  2. **依赖与成本**：需用户自带 API key（安全存放、费用失控防护是持续负担），与「小而完整、开箱即用」的公开叙事冲突；
  3. **时机**：当前主线是测试找 bug 与国庆公开准备，此功能非公开必需项。
- 远期触发再议：产品定位允许联网（如「显式开启的实验功能」B 案形态）或公开后产品演进时再评估，届时转 F 票。
